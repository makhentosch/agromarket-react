# АгроМаркет - фронтенд (React + Vite)

Каталог фермерских продуктов, вход и регистрация, оптовые заявки.
Данные берутся из REST API [agromarket-server](https://github.com/makhentosch/agromarket-server).

## Запуск

1. Запустить сервер `agromarket-server` (`npm run dev`, порт 3000)
2. `npm install`
3. `npm run dev` → `http://localhost:5173`

## Адрес API

Адрес сервера задаётся переменной окружения `VITE_API_URL` (см. `src/api.js`):

- локально - из файла `.env.development` (`VITE_API_URL=http://localhost:3000/api`);
- на хостинге - в настройках сборки;
- если переменная не задана - используется `http://localhost:3000/api`.

Vite читает `.env`-файлы только при старте - после изменения перезапустите `npm run dev`.

> **Внимание:** переменные `VITE_*` попадают прямо в собранный JavaScript и видны любому
> посетителю сайта. Класть в них можно только публичные значения (адрес API) - никогда
> `JWT_SECRET`, пароли или ключи.

## Скрипты

- `npm run dev` - режим разработки
- `npm run build` - сборка в папку `dist`
- `npm run lint` - проверка кода (oxlint)
- `npm run preview` - просмотр собранной версии

## Роли

- гость - видит каталог, может отправить оптовую заявку, войти или зарегистрироваться;
- покупатель (`user`) - то же, что гость, после входа;
- администратор (`admin`) - может удалять товары и видит список заявок.

Токен хранится в `localStorage`; при истёкшем токене приложение автоматически выходит из аккаунта.

## Тестирование

- `npm test` - компонентные тесты в режиме наблюдения, `npm run test:run` - один прогон (Vitest + React Testing Library + MSW)
- `npm run coverage` - отчёт о покрытии
- `npm run e2e` - E2E (Playwright) на локальном сайте: нужен запущенный локальный API; сначала `npm run dev`, иначе Playwright поднимет Vite сам
- `npm run e2e:smoke` - smoke-тесты `@smoke` против продакшена https://agromarket-makhentosch.vercel.app (только чтение); в CI ежедневно в 04:00 UTC и по кнопке Run workflow (`.github/workflows/e2e.yml`)

Перед первым запуском E2E: `npx playwright install chromium`. Для тестов администратора нужен файл
`.env.e2e` (в Git не попадает) с `E2E_ADMIN_EMAIL` и `E2E_ADMIN_PASSWORD` локальной базы.
Отчёт: `npx playwright show-report`.

## Лабораторная 10 - ответы

- **Сколько компонентных тестов и какие компоненты покрыты:** 21 тест в 5 файлах.
  `ProductCard` (5): название и цена, «В корзину» вызывает `onAdd`, «Удалить» только у админа,
  «Товар недели». `LoginForm` (5): отправка e-mail и пароля, пустые поля, e-mail без @, ошибка
  сервера, поле «Имя» только при регистрации. `Catalog` (7): загрузка, данные, ошибка 500, пустой
  список, сеть недоступна, поиск, удаление админом с токеном. `App` (3): заголовок
  `Authorization: Bearer ...` в запросах, ответ 401 возвращает к форме входа, гость не видит заявки.
  Плюс проверка настройки Testing Library.
- **Какие реальные дефекты нашли тесты:** форма входа не показывала своего текста ошибки при пустых
  полях и e-mail без @, полагалась только на всплывающие подсказки браузера; добавлена проверка
  с понятными сообщениями («Заполните e-mail и пароль», «Некорректный e-mail»). Каталог при пустом
  ответе сервера показывал пустой экран; добавлено «Товаров пока нет». Каталог вынесен из `App`
  в отдельный компонент `Catalog`, чтобы его можно было тестировать отдельно.
- **Покрытие:** Lines 84.03%. Хуже всего покрыт `ContactForm.jsx` (21%): отправку оптовой заявки
  не выполняет ни один компонентный тест, её проверяет E2E-сценарий покупателя.
- **Время:** компонентные тесты: 21 тест, само выполнение около 1,1 с (вся команда `npm test`
  около 6 с вместе с запуском jsdom). E2E на продакшене: 4 теста за 7,0 с, весь запуск в CI около
  38 с вместе с установкой браузера. На один тест E2E медленнее примерно в 30 раз.
- **Что увидели в trace упавшего теста:** в тесте каталога селектор заменили на
  `getByTestId('product-card-broken')`. В trace по шагам: открытие страницы, `goto /`, проверка
  заголовка (прошла), `toBeVisible` по сломанному селектору, ошибка `element(s) not found` через
  15 с. Для каждого шага есть снимок страницы, сетевые запросы и скриншот момента падения.
  Селектор вернули, тест снова зелёный.
- **Почему E2E не запускаем на каждый PR:** в PR код ещё не задеплоен, на продакшене работает
  старая версия, и тест проверил бы не те изменения. Кроме того, каждый запуск создаёт данные
  в боевой базе и идёт десятки секунд. Поэтому E2E запускается по расписанию и вручную,
  а в каждом PR работают быстрые компонентные тесты.
- **Сколько e2e-пользователей в базе и чем это плохо:** в Neon 2 пользователя `e2e+...` и 2 их
  заявки. Каждый запуск добавляет нового покупателя и заявку: тестовые данные смешиваются с
  настоящими, засоряют админку и статистику. Решение: отдельная ветка Neon для E2E или ночная
  очистка по шаблону `e2e+%`.

## Лабораторная 12 - ответы

- **Таблица «пирамида тестов»:**

  | Уровень | Что проверяет | Кол-во тестов | Время прогона |
  |---|---|---|---|
  | Сервер: Supertest (ЛР8, ЛР11) | API целиком с тестовой базой: права, валидация zod, rate limit | 52 | ~33 с |
  | Клиент: компонентные (Vitest + RTL + MSW) | компоненты и страницы с подменённым API: загрузка, пусто, 401, 429, 400 | 32 | ~16 с |
  | E2E: Playwright (локально) | браузер, React, локальный API и база вместе: регистрация, вход, заявка, админ | 9 | ~26 с |
  | Smoke: Playwright (продакшен) | главная, страница товара, прямая ссылка; ничего не меняют | 3 | ~4 с |

- **Какие недоделки нашли тесты:** у товара не было своей страницы и ссылки на неё, а вход,
  регистрация и админка были разделами одной страницы; добавлены маршруты `/products/:id`,
  `/login`, `/register`, `/admin` и переход гостя с `/admin` на вход. Подпись поля почты «Email»
  не находилась запросом `/e-mail/i`, теперь «E-mail». На Windows dev-сервер Vite слушал только
  IPv6, и Playwright его не видел; в `vite.config.js` задан адрес 127.0.0.1.
- **Почему API подменяется через MSW, а не vi.mock(fetch):** MSW перехватывает запрос на уровне сети,
  поэтому код компонентов и `apiFetch` проверяется без изменений, вместе с заголовками и разбором
  ответа. Обработчики описаны по адресам (`*/api/products`), один набор служит для всех тестов,
  а `server.use` в тесте подменяет только нужный ответ. Запрос без обработчика сразу даёт ошибку
  (`onUnhandledRequest: 'error'`).
- **Почему полные E2E нельзя запускать на продакшене, а smoke - можно:** полные E2E регистрируют
  пользователей, создают заявки и товары, то есть меняют настоящие данные. Smoke только открывает
  страницы и читает каталог. Проект `production` в `playwright.config.js` запускает только тесты
  с меткой `@smoke`.
- **Что показал трейс упавшего E2E-теста:** в тесте неверного пароля ожидаемый текст заменили на
  «пароль принят». Trace: `goto /login`, ввод e-mail, ввод пароля, клик «Войти», проверка текста
  упала с `element(s) not found` через 15 с; на скриншоте шага видна ошибка «Неверный e-mail
  или пароль» и адрес `/login`. Тест вернули.
- **Ошибку цены -500 в E2E показал браузер или сервер? Почему нужны обе проверки:** сервер. Поле
  цены без `min`, форма с `noValidate`, поэтому запрос уходит и zod отвечает 400 «Цена должна быть
  больше 0». Проверка в браузере удобна пользователю, но её обходят curl или Postman, поэтому
  сервер проверяет всегда.
