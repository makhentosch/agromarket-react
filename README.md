# АгроМаркет - фронтенд (React + Vite)

Каталог фермерских продуктов, вход и регистрация, оптовые заявки.
Данные берутся из REST API [agromarket-server](https://github.com/makhentosch/agromarket-server).

## Запуск

1. Запустить сервер `agromarket-server` (`npm run dev`, порт 3000)
2. `npm install`
3. `npm run dev` → `http://localhost:5173`

## Адрес API

Адрес сервера задаётся переменной окружения `VITE_API_URL` (см. `src/api.js`):

- локально - из файла `.env.development` (`VITE_API_URL=http://localhost:3000/api`);
- на хостинге - в настройках сборки;
- если переменная не задана - используется `http://localhost:3000/api`.

Vite читает `.env`-файлы только при старте - после изменения перезапустите `npm run dev`.

> **Внимание:** переменные `VITE_*` попадают прямо в собранный JavaScript и видны любому
> посетителю сайта. Класть в них можно только публичные значения (адрес API) - никогда
> `JWT_SECRET`, пароли или ключи.

## Скрипты

- `npm run dev` - режим разработки
- `npm run build` - сборка в папку `dist`
- `npm run lint` - проверка кода (oxlint)
- `npm run preview` - просмотр собранной версии

## Роли

- гость - видит каталог, может отправить оптовую заявку, войти или зарегистрироваться;
- покупатель (`user`) - то же, что гость, после входа;
- администратор (`admin`) - может удалять товары и видит список заявок.

Токен хранится в `localStorage`; при истёкшем токене приложение автоматически выходит из аккаунта.

## Тестирование

- `npm test` - компонентные тесты (Vitest + React Testing Library), ответы сервера подменяются моком fetch
- `npm run coverage` - покрытие: Lines 84.03%
- `npm run e2e` - E2E (Playwright) на локальном сайте: нужны запущенные API и `npm run dev`
- `npm run e2e:prod` - E2E на продакшене https://agromarket-makhentosch.vercel.app; в CI ежедневно в 04:00 UTC и по кнопке Run workflow (`.github/workflows/e2e.yml`)

Перед первым запуском E2E: `npx playwright install chromium`. Отчёт: `npx playwright show-report`.

  не выполняет ни один компонентный тест, её проверяет E2E-сценарий покупателя.
- **Время:** компонентные тесты: 21 тест, само выполнение около 1,1 с (вся команда `npm test`
  около 6 с вместе с запуском jsdom). E2E на продакшене: 4 теста за 7,0 с, весь запуск в CI около
  38 с вместе с установкой браузера. На один тест E2E медленнее примерно в 30 раз.
- **Что увидели в trace упавшего теста:** в тесте каталога селектор заменили на
  `getByTestId('product-card-broken')`. В trace по шагам: открытие страницы, `goto /`, проверка
  заголовка (прошла), `toBeVisible` по сломанному селектору, ошибка `element(s) not found` через
  15 с. Для каждого шага есть снимок страницы, сетевые запросы и скриншот момента падения.
  Селектор вернули, тест снова зелёный.
- **Почему E2E не запускаем на каждый PR:** в PR код ещё не задеплоен, на продакшене работает
  старая версия, и тест проверил бы не те изменения. Кроме того, каждый запуск создаёт данные
  в боевой базе и идёт десятки секунд. Поэтому E2E запускается по расписанию и вручную,
  а в каждом PR работают быстрые компонентные тесты.
- **Сколько e2e-пользователей в базе и чем это плохо:** в Neon 2 пользователя `e2e+...` и 2 их
  заявки. Каждый запуск добавляет нового покупателя и заявку: тестовые данные смешиваются с
  настоящими, засоряют админку и статистику. Решение: отдельная ветка Neon для E2E или ночная
  очистка по шаблону `e2e+%`.
